## 2. Key Findings & Engineering Trade-offs

1. **Inference Latency & Responsiveness**: Groq demonstrates ultra-low latency (4908 ms avg turn latency) compared to Gemini (4617 ms avg turn latency, ~0.9x difference). In patient voice interactions, this sub-second turnaround is crucial for maintaining real-time conversational flow.
2. **Multilingual & Indic Accuracy**: Groq achieved 50.8% on Hindi and 66.7% on Hinglish. Gemini achieved 50.0% on Hindi and 66.7% on Hinglish.
3. **Clinical Extraction Quality**: Groq achieved an extraction F1 of 60.5%, while Gemini achieved 63.9%.
4. **Deterministic Fallback Role**: The Mock LLM operates at zero API cost with 0 ms network latency (1 ms local compute). While limited to regex and heuristic pattern matching (45.3% F1), it guarantees uninterrupted intake availability if internet connectivity or third-party API quotas fail.

---

## 3. Architectural Distinction: Provider Extraction vs. Deterministic System Safety

A fundamental architectural principle in SwasthyaVaani is that **AI output is untrusted and physicians remain the final decision-makers**.

- **Provider-Dependent Layer**:
  - Entity extraction from natural patient speech (e.g. recognizing 'severe chest pain', pain intensity 9/10, radiation to arm).
  - Adaptive natural language follow-up question formulation in Hindi, Marathi, and English.
- **System-Level Deterministic Layer**:
  - Red flag safety rules ([`evaluate_red_flags`](file:///c:/Users/ACER/Downloads/SwasthyaVaani/backend/app/services/safety/red_flags.py#L5-L74)): triggers `RF-CP-001` or `RF-SEV-001` deterministically.
  - Contradiction detection ([`detect_contradictions`](file:///c:/Users/ACER/Downloads/SwasthyaVaani/backend/app/services/safety/contradictions.py#L5-L40)): identifies discrepancies between current statements and prior prescriptions.
  - Information sufficiency stopping & max question limits (`MAX_QUESTIONS=10`).

> **Important**: Safety events are NOT generated by LLM hallucinations; the LLM merely extracts the factual parameters that our deterministic safety engine verifies.

## 5. Scoring Methodology & Gating

The overall conversation performance score is calculated using the following transparent formula:

$$\text{Overall Score} = 0.30 \times \text{Extraction F1} + 0.25 \times \text{Question Relevance} + 0.15 \times \text{Efficiency Yield} + 0.10 \times \text{Language Handling} + 0.10 \times \text{Reliability} + 0.10 \times \text{Latency Score}$$

- **Safety Gating**: If a critical red-flag emergency scenario fails safety verification, the score is hard-capped to a maximum of 40.0.

## 6. Environmental Context & Limitations

1. **Network Latency**: API turnaround latencies reflect real-world network connectivity to provider endpoints (`api.groq.com` and Google GenAI endpoints) from the evaluation machine.
2. **Rate Limits & Fallback**: Live cloud providers may experience occasional rate limits or transient network latency spikes, which is precisely why SwasthyaVaani employs a multi-tiered fallback architecture (Groq -> Gemini -> Mock).
